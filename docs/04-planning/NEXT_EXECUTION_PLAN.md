## 1. 养护指南正确性与“动作优先”重构（P0）

### 1.1 先修规则错误

- 修复“水质浑浊→增加躲避物”错误关联。当前根因是“鱼缸中存在斗鱼”会让任意问题都追加躲避物；躲避物只能用于追咬、领地或繁殖场景。
- 逐项审计 8 类问题和 41 篇文章的“立即做 / 不要做 / 复查时间 / 下一步”，不由页面公共模板猜测动作。

### 1.2 重排文章与评测结果

- 首屏固定为：问题/风险、`现在先做`、最多 3 个编号步骤、`暂时不要`、何时升级处理、可执行主按钮。
- 每个具体动作使用动词标题和独立位置，不再埋在解释段落中；原理、完整证据和扩展阅读才允许折叠。
- 评测完成后只给当前结果对应的一个主行动，并在原结果中可见地记录“已执行 / 待复查”。

### 1.3 权威引用

- 为每篇文章和关键步骤增加可见来源，先使用 Merck Veterinary Manual、UF/IFAS Extension 和 RSPCA 等一手机构资料。
- 内容进数据库前先确认 `care_article_references` 与步骤 `actionTitle` 契约；引用必须直接支持对应动作，不能只在页底放一个泛化来源。
- 参考起点：[Merck 水族鱼管理](https://www.merckvetmanual.com/exotic-and-laboratory-animals/aquarium-fish/management-of-aquarium-fish)、[UF/IFAS 鱼类健康管理](https://edis.ifas.ufl.edu/publication/FA004.pdf)、[RSPCA 鱼缸环境](https://www.rspca.org.uk/adviceandwelfare/pets/fish/environment)。

## 2. 缸内体态调整改为三步任务（P0）

1. 选择要调整的批次和数量。
2. 选择生长阶段与繁殖状态，用图示卡和可点选状态，不使用原生下拉框。
3. 显示变更摘要并保存。

- 只修改部分数量时在同一流程自动拆分批次；整组修改不再要求用户理解“拆分”术语。
- 幼年、怀孕/抱卵、繁殖中、产后恢复继续只生成观察任务和内容推荐，不直接改变健康分或混养四态。
- 验收：一次只有一个主操作，可返回修改、可取消，重复提交不会重复拆分数量。

## 3. 鱼缸时间线与循环养护计划（P0）

### 3.1 鱼缸记录

- 在鱼缸标题右侧增加“鱼缸记录”，进入专用地址 `/aquarium?action=timeline&tank=<id>`。
- 从建缸开始按时间倒序展示：建缸/设置更新、加入/移出生物、体态变化、换水、喂食、巡检、养护计划完成。
- 旧数据只回填能从现有记录确认的事件，标注“由旧记录整理”；不伪造历史设置变更。
- 优先扩展现有 `care_events`，不建第二套鱼缸日志。

### 3.2 循环提醒

- 换水、喂食和通用养护计划可选“不提醒”或应用内循环；不申请系统通知权限。
- 默认快捷值：喂食 1/2/3 天，换水 3/7/14 天，通用计划 1/3/7 天，可自定义 1–90 天。
- 用户完成后以实际完成时间计算下一次，同时写入时间线；关闭循环不删除旧记录。

## 5. AI 与内容外部门禁（P1）

- 文字 AI：继续只保留 AI 建缸助手、异常/自由描述巡检解读和物种症状受控理解；正常结构化流程不调用 AI。
- 视觉 AI：等用户完成阿里云百炼开通后配置 `VISION_API_KEY / VISION_BASE_URL / VISION_MODEL`；未配置前继续明示“手动确认模式”。
- 建立清晰、模糊、多生物和非水族图片校准集，只报告 Top-1/Top-3 与未命中率，不在没有真实照片证据时承诺准确率。
- 生产 PostHog 事件需要部署环境变量和真实用户记录；当前只能声称事件契约和自动测试通过。

## 6. 性能、素材与真人验收（P2）

- 在真实低端手机采集 3D 五分钟首次可见、平均/最低帧率、GPU/内存、后台暂停和卸载释放证据后，再拆 `ThreeAquarium`。
- 处理构建警告：主包约 2.2MB，React Three Fiber 运行块约 889KB；不通过调高警告阈值隐藏问题。
- 重新生成 `sp_0357` 和 `sp_0452` 两张已确认破碎图，候选图人工确认后再替换版本并重跑 2D/3D 一致性。
